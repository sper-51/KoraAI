# Verda AI Investigator 前端原型提示词

你是一名资深产品设计师和前端原型工程师。请设计并实现一个可交互的中文 AI 竞品情报工作台原型，产品名为「青野 Verda」。不要制作营销落地页，第一屏直接进入可用的调研工作台。

## 产品定位

这是一个真实联网、证据可溯源、多 Agent 协作的竞品研究工具。用户输入一个竞品分析需求，系统动态澄清范围，自动组建专家队，调用联网搜索采集证据，进行交叉分析、质检和报告撰写，最后输出带引用、图表、知识图谱和决策回放的研究报告。

核心原则：无证据不立论；每个结论关联证据；搜索、抓取、去重和可信度评分属于确定性工具步骤；只有需求理解、团队派遣、分析、舆情分类、质检和写作等步骤显示 LLM 调用信息。

## 视觉方向

- 中文桌面端优先，同时适配平板和手机。
- 安静、专业、可信、偏研究工作台，不使用营销式大 hero、渐变背景、装饰性光球或堆叠卡片。
- 主色为低饱和植物绿，配米白背景、深墨色正文、浅灰边框、少量暖黄色强调；避免整页深蓝或紫色。
- 细边框、最多 8px 圆角、轻阴影、紧凑但易扫描的信息密度。
- 使用 Lucide 图标；按钮中图标优先，熟悉的操作使用图标按钮并提供 tooltip。
- 标题使用有编辑感的衬线字体，正文使用清晰的无衬线字体。
- 所有状态都要有 loading、empty、error、success、disabled 和 mobile 版本。

## 全局布局

桌面端使用左侧固定导航栏，右侧为可滚动主内容；任务工作区、报告阅读页和知识图谱使用自己的全屏布局。

左侧导航：

1. Verda 标志（嫩芽图标）和品牌名。
2. 工作台 `/`。
3. 我的调研 `/library`。
4. 知识库 `/knowledge`。
5. 专家公会 `/experts`。
6. 竞争情报中心 `/dashboard`。
7. 底部显示工作空间完成次数、已沉淀证据数和当前用户“林研究员 / 青野科技”。

## 页面与流程

### 1. 工作台首页 `/`

这是默认入口，不做营销首页。

- 顶部显示“新功能上线”和用户头像。
- 中央显示问候语“下午好，林研究员”，副标题“你的 AI 竞品分析 Agent —— 48 位专家协作，无证据不立论”。
- 主输入框支持多行，placeholder：`想分析哪个市场、公司或竞争策略？例如：分析 Notion / 飞书 / Obsidian 的产品与定价竞争格局`。
- 输入框底部提供三档调研模式：
  - 快速：5 章，约 2 分钟，速览。
  - 深度：9 章，约 4 分钟，含返工闭环。
  - 专家级：12+ 章，约 6-8 分钟，创新板块和最深分析。
- 右下提供模型选择、附件按钮和提交按钮。提交按钮在空输入时禁用；支持 Ctrl/Cmd + Enter 提交。
- 提供四个示例任务：新能源车竞争格局、竞品 SWOT、功能对标基准、市场趋势报告。点击示例立即提交。
- 底部展示 48 位专家头像墙，点击进入专家公会。

交互：提交后调用 `POST /api/tasks`，传入 `{query, mode}`。若返回 `needClarify=true`，跳转 `/clarify/:taskId`；否则跳转 `/workspace/:taskId`。

### 2. 动态澄清问卷 `/clarify/:taskId`

页面必须支持后端动态返回的问题，不要把问题集合硬编码在前端。

可能的问题类型：

- `scope`：模型识别的调研对象和所属领域确认。
- `competitors`：模型自动发现的候选竞品，多选，可输入自定义竞品并回车添加。
- `focus`：功能、定价、口碑、市场份额、SWOT、舆情趋势、技术架构、增长、商业模式、生态壁垒，多选。
- `perspective`：产品经理、运营、销售、用户/消费者、投资人、通用/综合，单选。
- `market`：中国大陆、全球、北美、东南亚、欧洲、不限，单选。
- `user`：个人用户、中小团队、大型企业、开发者、学生教育、不限，单选。
- `freshness`：优先最新、近一年、不限时间，单选。
- `extra`：自由文本补充、纠正或背景。

每道题显示题目、可选 hint、单选/多选 chip 或文本框。页面顶部回显用户原始需求。底部提供“跳过并开始”和“启动调研”两个操作；提交调用 `POST /api/tasks/:taskId/clarify`，然后跳转工作区。

必须展示动态识别失败时的可用降级状态，但不要伪装成动态结果：提示“未能完成自动识别，仍可手动补充范围”。

### 3. 实时任务工作区 `/workspace/:taskId`

全屏三栏布局：

- 左栏约 280px：任务流水线 DAG 和专家队头像。
- 中栏自适应：实时协作思维流。
- 右栏约 340px：实时证据流和联网图片。

顶部：返回按钮、任务名称、任务 ID、证据数量、进度条和百分比。

左侧流水线节点：

1. 需求理解 `intake`
2. 编排派遣 `orchestrator`
3. 证据采集 `collect`
4. 交叉分析 `analyze`
5. 报告撰写 `write`
6. 质检审裁 `audit`
7. 签发交付 `done`

每个节点支持 idle、working、done、rework、error 状态。返工时要明显显示“证据不足，补采”或“按质检意见重新分析”。

中栏思维流按时间追加事件：action、finding、reflect、claim、audit_review、rework。每条事件包含专家头像、专家姓名、阶段标签、正文和时间。内容到达时有轻微打字/淡入动画，自动滚到底部，但允许用户暂停滚动。

右栏：

- 证据计数。
- 实时 Evidence 卡片：标题、来源类型、域名、摘要、可信度、品牌和原文链接。
- 联网抓取图片网格，图片失败时隐藏并保留证据卡片。
- 没有证据时显示“尚未采集到可用证据”，不要展示虚构数据。

右下悬浮 Trace 面板：

- 显示累计 token 和步骤数。
- 每条记录显示阶段、专家、purpose、模型、token、耗时。
- LLM 步骤显示真实模型信息。
- 搜索、网页抓取、去重、规则评分步骤显示：`—（检索/规则，无 LLM）`、`0 tok`，这是正常工具步骤，不应伪装成模型调用。
- 支持展开查看 Prompt、Output、关联证据；支持折叠、关闭和重新打开。

数据流使用 `GET /api/tasks/:taskId/stream` 的 Server-Sent Events。处理事件：`node_update`、`thought`、`message`、`evidence`、`chart`、`image`、`progress`、`trace`、`report_ready`、`done`、`error`。断线时显示可重试错误条。

完成后显示“报告已签发，正在打开”，短暂停留后跳转 `/report/:reportId`。

### 4. 报告阅读页 `/report/:reportId`

采用三栏阅读器：

- 左侧目录和阅读进度。
- 中央报告正文。
- 右侧知识库/标注/证据来源。

顶部显示报告标题、副标题、创建时间、模式、专家数量和操作按钮：返回、知识图谱、知识库、Trace、编辑。

报告封面下方显示四个指标：核心结论、联网证据、独立信源、高置信占比。

正文章节支持：

- 章节标题、关键结论、highlights、段落、Claims。
- 章节级证据引用 chip，点击滚动并高亮右侧对应证据。
- 功能矩阵、定价表、用户画像卡、数据空间表格、ECharts 图表。
- 全网舆情章节、情感分布、平台声量和代表性原声。
- 联网实景图集，每张图片可点击回到原始页面。
- 术语表和采集方法说明。

正文编辑与标注：

- 编辑模式下双击段落修改。
- 选中文字后弹出浮动工具条：高亮、批注、收入知识库。
- 高亮支持颜色、评论、删除和从右侧标注列表跳回原文。
- 点击“收入知识库”写入本地持久化知识库。
- 对章节提交批注后调用 `POST /api/reports/:reportId/refine`，展示局部刷新和处理中状态。
- 支持提交人工反馈，计算人工修正率。

### 5. 知识图谱 `/graph/:reportId`

使用全屏画布展示“报告 → 结论 → 证据”的关系网络：

- 报告节点为深绿大圆。
- 结论节点为中绿。
- 证据节点为暖黄色。
- 节点可拖动，画布支持滚轮缩放和平移。
- 顶部显示图例和返回报告按钮。
- 节点 hover 显示完整标题；点击节点可聚焦关联关系。
- 空数据时显示空状态和返回报告操作。

### 6. Trace 决策链路 `/trace/:reportId`

纵向时间线展示完整 Agent 决策链路。顶部显示总 token、总耗时和步骤数；支持按阶段筛选：全部、需求理解、编排派遣、证据采集、交叉分析、报告撰写、质检审裁、签发交付。

每个 Trace 卡片可展开：专家头像、阶段、purpose、模型、输入 token、输出 token、耗时、Prompt、Output、关联 evidence IDs。规则采集卡片要明确标为“检索/规则，无 LLM”，不能把 0 token 渲染成错误。

### 7. 我的调研 `/library`

- 标题“我的调研”和“发起新调研”按钮。
- 报告卡片网格：封面、标题、副标题、创建时间、证据数量、高置信数量、知识图谱入口。
- loading 显示 skeleton。
- 空状态显示插图、说明和“开始调研”。
- 点击卡片进入报告；点击图谱图标进入图谱。

### 8. 知识库 `/knowledge`

- 显示知识总数和说明。
- 搜索框按内容、报告标题和标签过滤。
- 类型筛选：全部、论点、证据、金句、配图、摘录、高亮。
- 按报告分组展示条目。
- 每条显示类型、品牌、正文、标签、图片和原文链接。
- 支持移出知识库。
- 空状态区分“知识库为空”和“没有匹配内容”。

### 9. 专家公会 `/experts`

- 展示 48 位专家，支持按层级/组别筛选和按姓名、技能、标签搜索。
- 分为决策层 L3、策略层 L2、执行层 L1。
- 专家卡显示头像、姓名、职称、简介、技能标签、历史任务和证据统计。
- 点击进入 `/experts/:id`。

专家详情页：

- 返回专家公会。
- 大头像、姓名、角色层级、角色介绍、知识标签、技能、累计工作量。
- 显示同组协作专家，点击可跳转。

### 10. 竞争情报中心 `/dashboard`

这是全局数据看板，不是单份报告页面。

- 顶部指标：覆盖竞品、情报证据、产出结论、交叉验证率。
- 业务闭环价值：累计节省人力、平均效率提升、平均覆盖提升、人工修正率。
- 研究报告卡片：查看报告、Trace。
- 竞品情报厚度：按品牌显示证据数量、来源类型数、平均可信度、最近采集时间。
- 信源结构：权威一手、媒体报道、社媒口碑的比例和解释。
- 全局证据库支持按品牌、来源类型、最低可信度过滤。
- 竞品监控订阅：输入赛道/查询创建订阅，列表显示并支持删除。
- 专家贡献榜：任务数、产出论点、采集证据，点击进入专家详情。
- 空状态和加载状态必须完整。

## 数据契约

使用以下 API 形态设计 mock 层和真实接口适配层：

- `POST /api/tasks`：创建任务。
- `POST /api/tasks/:taskId/clarify`：提交问卷。
- `GET /api/tasks/:taskId/stream`：SSE 实时任务流。
- `GET /api/reports`、`GET /api/reports/:reportId`：历史报告和报告详情。
- `GET /api/reports/:reportId/trace`：报告 Trace。
- `POST /api/reports/:reportId/refine`：按批注深化章节。
- `POST /api/reports/:reportId/feedback`：人工反馈。
- `GET /api/evidences`：全局证据库。
- `GET /api/experts`、`GET /api/experts/workload`：专家和工作量。
- `GET/POST/DELETE /api/subscriptions`：竞品监控订阅。
- `GET /api/dashboard`：看板统计。

所有请求需要有错误兜底：网络失败时显示可理解的中文提示；空数组显示空状态；不要用随机数据冒充真实结果。原型模式可以使用固定 mock 数据，但数据结构必须与上述契约一致，并在界面标记“演示数据”。

## 状态与验收标准

请实现并验收以下全流程：

1. 从首页输入需求并选择模式。
2. 创建任务后进入动态问卷。
3. 完成动态问卷并进入工作区。
4. 工作区实时显示 DAG、专家队、思维流、证据、图片、进度和 Trace。
5. 支持规则采集步骤的明确展示，不把规则步骤误标为 LLM。
6. 支持错误、断线、无结果、补采返工和最终完成状态。
7. 自动进入报告页。
8. 报告目录跳转、证据引用高亮、图表、结构化表格、图片溯源可用。
9. 选中文字后可高亮、批注、收入知识库；知识库页可搜索和移除。
10. 报告可进入知识图谱和 Trace 页面，筛选、展开和返回均可用。
11. 历史报告、全局看板、专家公会和专家详情均可从导航访问。
12. 移动端不出现横向溢出，关键操作可触达，三栏工作区在窄屏转换为上下分区或抽屉。
13. 键盘可操作，按钮有可见 focus 状态，图标按钮有 tooltip，图片和表格有可读的替代文本。

请输出：完整页面原型、组件层级、路由表、状态机、mock 数据、API 适配层、桌面/移动端布局以及可运行的交互演示。优先保证全流程可点击和状态完整，再进行视觉细化。
